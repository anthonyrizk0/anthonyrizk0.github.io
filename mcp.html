Streamable HTTP, stateless, no authentication and no headers to set. If your client speaks MCP over HTTP, the URL is all it needs.

What it's good at

It answers from a corpus I write and maintain — roles, projects, the decisions behind them, and a fair amount that never fit on the résumé. It is not searching the web, and it will tell you when something isn't covered rather than guessing.

Three things worth knowing before you point an agent at it:

  • Each call is independent. There's no session and no memory between questions, so a follow-up like "how did that compare?" won't resolve. Restate what you mean.
  • Narrow beats broad. "What has he built recently?" returns concrete projects; "what is he up to?" returns a summary. Specific questions get named technologies, decisions and outcomes.
  • A refusal is an answer. If it says something isn't covered, rephrasing and retrying won't find it — the corpus declines rather than inventing, and pressing is how you'd get a wrong answer instead of no answer.

No auth, on purpose

The browser version is gated by Turnstile, which proves a human rendered a page. There's no agent equivalent, and a token published on a public page isn't a secret — so gating this would be theatre that also defeated the point.

Instead it's bounded by the things that actually work on an open endpoint: a rate limit, a hard deadline on each generation, and a daily spend cap that closes this endpoint before it touches the website's. If you ever get told it's reached its limit for the day, that's what happened — the Ask box will still be answering, and it's the same corpus.
